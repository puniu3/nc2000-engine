探索回数だけを変える比較。ソルバ・評価関数・情報・探索方針は比較対象から外しています。

現時点の判断

選出に予算を寄せる配分は有望です。ただし、最適点はまだ確定していません。選出だけ81kにすると、総探索量は同じ試合長なら約8%増で、対27kの得点率は58.3%。選出だけ243kでは約32%増で64.6%でした。全体81kは探索量3倍で56.3%です。選出への追加計算は1試合に1回なので、全体を増やすより小さな費用で改善を狙えます。

各設定48試合・24組なので、配分同士の優劣にはまだ大きな幅があります。選出81kと全体81kの差は+2.1ポイント、95%区間は−10.4〜+14.6ポイント。選出243kと81kの差も+6.3ポイント、区間は−8.3〜+20.8ポイントです。「選出だけ増やせば全体増量より強い」「81kで飽和する」とは言えません。

27k→81kでは15 / 48局面で選出が変化し、内訳は先発6、3匹の組合せ8、控え順のみ1でした。81k→243kでも5 / 48局面で変化しました。例えば、対sample-11のrental-cban-13は、81kの「ナッシー・カビゴン・ニョロボン」から243kの「ゴローニャ・カビゴン・ニョロボン」へ変わっています。個々の変更の改善効果は、選出後の乱数を揃えた別の追試が必要です。

指定された実装方針に沿い、既知パーティの選出は事前計算へ移します。未知パーティの予算は別標本で飽和を測って決める必要があり、243kは10秒程度という許容時間に照らした測定候補です。対戦中の段階は、既に比較した27k・81kを候補とし、3段階目は追加測定後に決めます。今回、製品の設定やUIは変更していません。

1回の選出に多く使うと、総量はどのくらい増えるか

対戦中の探索判断が 30 回ある場合。強制手には探索を割り当てません。

総探索量 = 選出予算 + 対戦中の判断回数 × 対戦中予算

この図は回数の計算であり、勝率・待ち時間の予測ではありません。試合展開による判断回数の変化も含みません。

公開版への適用で変わる点

選出では強さを優先し、10秒程度まで許容するという利用者の希望を確認済みです。選出243kも実用候補に含めます。前回のMac Chromiumの選出1局面では、27kは0.60～0.61秒、81kは1.96～2.10秒、243kは6.65秒でした。iPad Safariの実測ではありません。

公開版は、人間が考えている間に最低予算27kを超えて、最大270kまで先読みします。選出に時間を使う利用者では、すでに81k以上を読んでいる可能性があります。選出の最低値だけ上げても、その利用者に追加の探索は発生しません。

現在の実装で27kを81kへ単純変更すると、上限も270kから810kへ増えます。利用者が指定した次の設計では、この伸び縮みを廃止し、先行して思考を開始したうえで固定回数で終了させます。今回の先読みなし比較は固定予算の比較ですが、現行公開版・対人戦の改善幅を直接示しません。

調査後の実装方針（利用者指定）

既知パーティの選出は事前計算してビルドに含め、未知パーティには効果の飽和を測定した探索数を使います。対戦中は2〜3段階の固定予算をプレイヤーが選びます。プレイヤーの選択中に計算する仕組みは維持し、早打ち・長考で探索回数が変わる仕組みは廃止します。同じ局面・乱数・選択した予算なら、入力タイミングにかかわらず探索回数と判断が一致することを確認条件にします。

今回の標本は既知カタログです。未知パーティの飽和点をこの結果から決めることはできません。旧選出テーブルの仕組みは残っていますが、現行カタログ用テーブルはなく、旧60候補の扱いも現行の順序付き選出に合わせて再検証が必要です。テーブル参照は公開情報から特定できる相手に限り、非公開の技・持ち物をキーとして漏らさない条件を維持します。対戦中243kの優位性も今回の比較対象には含みません。

比較方法と確認

製品カタログのdrawWeightに従ってチームを抽選。相手は全判断27k。24組のチーム・対戦乱数・座席ごとの探索乱数を共通にし、各設定で担当側を入れ替えた2局を実行します。全240局を事前固定し、設定と座席の実行順を混ぜています。

対戦の進行・探索乱数・観測を保持したまま、選出か対戦中かで反復数だけを変更。予算を変えない場合に既存agentと判断・乱数列が一致する試験を通過。さらに同じ設定同士12局で、時間を除く全状態・行動列が一致する対照を確認しました。反復数を変えると乱数の消費量も変わるため、同じ選出になった試合でも後の展開が完全一致するとは限りません。

96局完了時点で、利用者の依頼に従い残りを分割しました。最終的な割当はMac195局、Google Cloud Batch45局です。比較するチーム・乱数・予算・局数は固定したままです。異なるCPU間の確認用2局は得点に含めず、状態・行動・結果が一致することを確認して結果を統合しました。所要時間はCPU別に分けて記録しました。Cloudは準備時の2件の不備を修正し、最終実行では時間上限までに45局を完了しました。未完了3局は同じ条件でMacで補完しました。3回の起動を含む費用見積は約103円（クレジット適用前・請求額ではありません）。全ジョブのリソース削除を確認済みです。実行記録。

得点は勝ち1・引き分け0.5・負け0。同じ組の2局をクラスタとして10万回bootstrapし、設定間の差も組を対応させて計算します。公開WASMと今回のnativeは完全に同じ成果物ではありません。現行の公開設定は変更していません。
