# Bounded screen of native endgames

The complete 360-root census is screened with 25,000 engine executions and 5,000 nodes per root, standard cell cap 4,096, loss tolerance 0.02 and four independent workers. Every legal pure first action of the current side is a loss-refinement target. Remaining BoundConfig fields use the frozen runtime defaults printed in each result. Unresolved and node-budget-limited roots remain in the output. Four smoke roots (sorted indices 0, 120, 240, 359) informed feasibility only; the complete census includes them.

This is a perfect-information diagnostic on actual state, using the solver's independent chance-class model. It is not a solution of the blind game or an analysis against human players. Root cells represent optimal continuation after both first actions. Pure-action minimax loss need not imply a mixed-policy error: an equilibrium may intentionally randomize over such actions. Strict domination is therefore reported separately as the lower bound on an alternative action's advantage against every opponent first action. Even that certificate applies only to the fixed hidden world until extended to the bot's information set.

Build native_endgame_bounds.rs as a bot example in the current native serialization adapter at tmp/hp-native-current, copy its release binary before building any other worktree, and invoke it with PROTOCOL ROOTS DEX OUTPUT. Inputs are the preserved native-endgame-census-v1 snapshots and the frozen dex used by native-deployed-duel-v1. The output is created exclusively and flushed after each root. No runtime source, sleep-counter handling or Counter rule is changed.
