混合方策を保持して実行する構造へ

可能です。通常対局と棋譜からの再開に、確率分布を返し、その分布から一度だけ抽選する経路を実装しました。既定値は従来方式を維持し、混合方式を実験設定で選べます。

何が問題なのか

同時手番でも純粋均衡があるゲームはあります。また、探索中・実対局中に一回につき一手だけ実行することは正常です。問題になるのは、混合が必要な局面で、確率分布を最後に最多訪問の一手へ潰してしまうことです。

現行の通常手は argmax(visits) です。探索seedを変えれば選択も変わるので、seed全体で見たbotまで常に純粋とは限りません。しかし、その間接的な混合は均衡を狙って制御された確率ではありません。選出表など、以前から混合を使う別経路もあります。

一般のゼロ和同時手番では、純粋手に制限した maxₐ minᵦ Q(a,b) と、分布を許す maxₚ minᵦ Σₐ p(a)Q(a,b) が異なり得ます。さらに Q は相手の応手と、その後の方策を含む価値です。最後の抽選だけ直しても、探索途中の評価がその混合を扱えなければ最適性は得られません。

新しい決定経路

観測・探索→ 合法手の確率分布 π→ 一度だけ抽選→ 一手を提出

Rustの共通 DecisionPolicy が分布を検証・正規化し、低確率の正の成分を閾値で切り捨てません。Protocol側は合法な入力表現へ分布全体を対応づけ、同じ入力へ集まった確率を合算します。抽選用乱数は探索用乱数から分離しました。

API意味
playPolicy(mode)実行する分布。読むだけでは抽選しない。
commitDecision(mode){input, policy} を返して確定。繰り返しても引き直さない。
rootPolicy()従来の訪問数・平均値。frac は実行確率とは区別。

次の observe / onRequest / setPosition で決定を更新します。確定後に探索を追加しても、確定済みの手と分布は維持します。対局seedからの再現可能な乱数であり、暗号学的な予測不能性は保証しません。

抽選した今回の一手は「のろい」でした。混合方式でも、その都度の出力は一手です。分布が保持されていることと、勝率が上がることは別の検証事項です。実測JSON

既存の混合推定器の0.02判定閾値と探索方法は維持しました。非定常な探索平均から作る推定値に、厳密な信頼区間や均衡の保証は付けていません。従来の選出表で既に抽選済みの手は preview-sampled と明示し、その抽選後の条件付き点質量を返します。これは表全体の混合分布の公開ではありません。

次に解くべきクラス

狙う構造は「情報集合 → 全合法手上の分布 → 相手の各応手との組合せ → 後続の混合方策を含む価値」です。既知の有限ゲームでは行列ゲームの後退計算、隠れ情報がある場合は同じ情報集合で共通に実行できる方策が必要です。前回の区間評価器が返す分布も共通APIに載せられますが、通常のblind探索はまだその厳密な価値境界を供給できません。

探索の各節点を単純にno-regretへ変えるだけでも十分ではありません。同時手番以外は完全情報のゲームですら、観測利得をそのまま使う局所学習は均衡への収束を保証しないことが示されています。これは現在の隠れ情報botへの直接の収束証明ではありません。Kovařík・Lisý, Analysis of Hannan Consistent Selection for Monte Carlo Tree Search in Simultaneous Move Games
