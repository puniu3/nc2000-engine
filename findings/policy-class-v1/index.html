NC2000 / 2026年10月17日 / 原因分析と一般化した選択処理

「最多の一手」への変換が、混合方策の価値を消している

今回の反例は、相手の応答によって有利な手が逆転し、少数派の手にも抑止力がある同時手番の一例だった。探索が最適な行動頻度を完全に学習していても、その最多の一手だけを採用すると非最適になる。探索精度と、探索結果から実行方策を作る処理を分ける必要がある。

今回、技名に依存しない区間値による方策選択を実装した。既知の有限ゲームでは、現行方策の継続値を評価し、保証値を改善する分布へ更新することで、この問題のクラスを解ける。通常のblind対戦で使うには、同じ情報制約で実行できる継続方策の値を用意する必要が残る。

1. コードとデータから確定した原因

ソースの標準経路は WasmBlindSearcher.best() → BlindSearch.best()。後者は合法・除外条件を満たす手から最多訪問の一手を返す。rootPolicy() の frac は探索中の訪問割合であり、実際のプレイ確率ではない。別に実装されている混合方策を返す経路は、現行の通常プレイでは使われていない。今回の公開版36探索と前回128探索でも、最多訪問の手を選ぶことが一致した。

前回の公開版128探索を固定して、最後の分布の作り方だけを変えて評価した。以下は同じ真の構成・最適な将来の継続を仮定した初手の保証スコア（勝ち1・引き分け0.5）。変更後のbotを対戦させた勝率ではない。

平均訪問割合は最適配分に近いが、各探索を個別に訪問割合でプレイした場合の最小保証値は0.317%だった。「訪問割合を使う」は有望な対照実験になる一方、あらゆる局面の一般解にはならない。探索には試行のための配分が含まれ、相手の探索方策と将来の評価も途中で変化する。

2. 個別の技から、資源つきの読み合いへ

相手が防御的な応答をあと k 回使える、次の抽象ゲームを考える。攻撃同士が重なった場合の成功値を g、残り k 回での最適値を Vk とする。

自分 ＼ 相手攻撃防御的な応答
攻撃g0
待機0Vk−1

V₀ = g。攻撃確率を p とすると、相手は p·g と (1−p)·Vₖ₋₁ の小さい方を実現する。この二つを釣り合わせると、

pₖ = Vₖ₋₁ / (g + Vₖ₋₁) = 1 / (k + 1)
Vₖ = g·Vₖ₋₁ / (g + Vₖ₋₁) = g / (k + 1)

「1〜k+1回目から最初の攻撃時機を一様に選ぶ」と同じ。残り資源が減るたびに確率が変わる。k が1以上なら、攻撃一択も待機一択も保証値0。これは探索回数を無限に増やしても、最後に一手へ潰す限り残る構造的な損失である。

確率を動かして確認する

抽象モデル g=1。グラフは相手の最悪応答を選んだ保証値。アニメーションは使用していない。

これは全ての待機局面に適用するルールではない。追加の逃げ道や別の手がある場合には、その応答も含めて値を検査する。今回の実局面では交代を含む全合法手で値を計算し、0〜7の各残り回数が上式と一致する区間に入ることを確認した。

3. 初手だけ混ぜると、なぜまだ失敗するのか

上の右下の値は、将来も適切に混ぜる場合の値である。初手だけ12.5%対87.5%にして、その後は待機一択へ戻すと、相手は最初に防御的な応答を選べばよく、保証値は0になる。毎回同じ12.5%を使い続けても、残り7回の抽象ゲームの保証値は約4.49%で、最適な11.43%に届かない。

したがって、「最適に継続した場合の値」で初手を評価し、「従来bot」で継続するという食い違いを避ける必要がある。前回の純粋な勝率下限10.57%は、初手だけでなく攻撃時機を決めた継続方策を直接列挙して得たものだった。

全体の一般解は、現行方策 π をいったん固定して、その継続値 Q^π(s,a,b) を評価する方策改善で表せる。

Q^π の下界 L と上界 U を用意する
p = argmaxₚ min_b Σₐ p(a) L(s,a,b)

min_b Σₐ p(a) L(s,a,b)
  > min_b Σₐ π(a) U(s,a,b)
なら、その状態の π を p に置き換える

既知の有限・非循環ゲームでは、末端からの帰納法で、こうした更新が全状態の最悪応答に対する値を下げないことを示せる。正確な継続値を使って繰り返せば、ゲーム木の深さに応じた回数で最適方策へ到達する。区間が広いときには改善判定がつかず、元の分布を保持する。

実装した root_policy::interval::analyze は、この判断を行う技名非依存の選択器。単一行動への丸めや、小さい確率の切り捨てをしない。純粋戦略が適切な局面では純粋戦略を返す。既存のLP解法を再利用し、既存botの標準経路にはまだ接続していない。数値誤差のため上下界に2×10⁻⁸の余裕を取り、有理数による形式的証明とは区別している。

4. 一般化で落としてはいけない条件

  • 全ての合法応答を見る。良さそうな2×2部分行列だけを解くと、除外した交代や別技に負ける。未評価のセルは都合のよい平均値で埋めず、[0,1]のまま扱う。
  • 少数派の手を消さない。今回のクラスでは、資源が増えるほど必要な攻撃確率が小さくなる。別の実験用RM経路にある「最大確率の半分未満を除く」処理なら、k≥3の必要な手も消える。現行公開版の直接原因はargmaxであり、この閾値処理が動いた結果ではない。
  • 固定の改善幅を隠さない。既存の実験用混合ゲートは2ポイント超を要求する。一方、今回のゲンガー側の混合利得は約1.633ポイントなので、値が完全に正しくても通らない。新APIでは必要改善幅を引数として明示し、今回の検証では数値誤差の余裕だけを残した。
  • 隠れた構成を平均してから相手の最善応答を取らない。相手は自分の構成を知っている。既知のタイプ確率 w なら Σθ wθ min_b Σₐ p(a)Qθ(a,b) の順番になる。順番を逆にすると、実際には不利な混合を有利と判定できる。確率分布が不明な場合の、指定した全タイプに対する最悪値もAPIで分けた。
  • 将来も情報制約を守る。各隠れた世界で別々に最適な行動をした値は、blindプレイヤーが実行できる下界にはならない。同じ観測履歴では同じ方策を使う必要がある。
  • 探索用の乱数と実行用の抽選を分ける。実行する手は得られた分布から決定点ごとに一度抽選し、照会のたびには抽選し直さない。探索seedによってargmaxが揺れることを、意図した混合の代わりにはしない。

探索節点ごとに後悔を小さくする手法へ置き換えるだけでも、観測した報酬をそのまま用いた木全体の均衡収束は一般には保証されないことが研究されている。これは過去の有限予算の失敗を直接証明するものではなく、「EXP3等に替えれば全体も自動的に正しくなる」と仮定できない根拠となる。Kovařík・Lisý, Analysis of Hannan Consistent Selection for Monte Carlo Tree Search in Simultaneous Move Games。

実装済みの部分と、残る主課題

保証された継続値がある有限モデルについて、混合を壊さず方策を改善するクラス共通の処理を実装・検証した。残る主課題は、通常のblind対戦の予算内で、実行可能な同一継続方策の値・誤差範囲を作ること。非定常な探索平均をそのまま証明済み区間として渡すことはできない。

この結論は、従来の全ての強化実験が失敗した理由を一括して説明するものではない。今回は、出力時の分布の消失を構造的な原因として確定し、継続値・情報制約・固定閾値を別々の問題として切り分けた。公開botの変更・再公開、通常対戦の平均勝率向上の判定は行っていない。
