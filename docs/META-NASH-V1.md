## 合格条件（オーナー設定 2026-08-12、ORゲート）

どちらか一方の成立で合格:

- **Gate A（多様性ルート）**: テンプレート通りでない数十のパーティ混合 & 現状より
  弱くならない。「AIが自力で編み出したパーティ」というストーリーを維持しつつ、
  現実との接触で瓦解しない。
- **Gate B（強さルート）**: 敵対的な exploiter に現状よりも確実に強い。プールが
  痩せても勝っていれば「ゲームの結論が出た」というストーリーが成立。

### 操作的定義（プレレジ、結果開封前に固定）

**Gate A:**
- プール = **進化由来チームのみ**の maximin 混合(列空間 = 全候補)、ε-スムージング可。
- 「数十」= **重み ≥ 1% のチームが 24 以上**。
- 「テンプレート通りでない」= 正規化フルセット署名がキュレート34のどれとも不一致、
  かつ相互に不一致。種族構成の類似は不問(メタの再発見は成果であって欠格でない)。
- 「弱くならない」= AIプールbot vs 現行bot(キュレート34一様抽選、同一エージェント)の
  seed-paired プール対戦で、**300反復 n=1600 と 1000反復 n=800 の両方**において
  点推定 ≥ 0.48 かつ 95%下限 ≥ 0.45。
- ε はこの2条件(数十 + 非退行)を同時に満たす最小値を選ぶ。maximin値からの低下も記録。

**Gate B:**
- 対象プール = 全候補上のナッシュ混合(full)。基線 = キュレート34一様。
- exploiter 探索: 各対象に **同一予算**の (1+λ) 山登り 3系統(種: 最強キュレート /
  ランダム / 対象サポートの変異)、fitness = 対象の重み付きサポートガントレット。
- 最終測定: 各対象の最良 exploiter(holdout選抜)を新シード・高n(重み付き ≥1000戦)で
  再採点。**合格 = 新プールへの被搾取スコア < 現行への被搾取スコア、95%CI非重複**。
- 併記: DO停止マージン(候補集合内BR値 − 0.5)。

## 方法（要点のみ; 機構は全て在庫)

1. 候補集合 T₀ = キュレート34。ペアワイズ行列を `gauntlet_eval`(skuct:300、seed-paired、
   64戦/セル、resumable)で推定、サポートペアは192戦に精密化。
2. `solve_rm_plus` でナッシュ混合。
3. BR オラクル = `TeamGen` の (1+λ) 山登り(CRN + holdout、M11a の作法)、fitness =
   現行混合サポートへの重み付き勝率。ランダム種 8 + プール種 4 系統 → 受理チームを
   署名dedupeで収穫(≤4/系統)して T に追加 → 行列拡張 → 解き直し → BRマージンが
   +0.03 未満か 4 ラウンドで停止。
4. 成果物: `data/meta-nash-v1/`(candidates / cells / lineages / solutions / gates)、
   最終 `pool-artifact.json` {teams, weights, provenance}。web は既存のファイル読込
   プール + 重み付き抽選(botの自チーム選択のみ; 相手beliefは不変)。

## 既知の留保(プレレジ)

- 行列・進化・ゲートは skuct:300/1000 の研究予算。30k製品プレイへの転移は未検証のまま
  出荷判断する(M17bの知見: 予算間の挙動差は小さい)。
- M11旧データはレギュレーション移行前のため数字は不使用(機構のみ再利用)。
- 「exploiterに強い」は適応型相手への防御であり、非適応相手への平均勝率向上を
  約束しない(M8 end-to-end probe = null)。Gate B が測るのは前者。
